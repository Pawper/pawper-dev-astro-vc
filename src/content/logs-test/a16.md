When you name a feature privately, you have the luxury of revision. The name lives in a Notion doc or a Slack thread, and if it's wrong you change it. When you name a feature publicly — in a URL, in a heading, in a changelog — it accretes. Users search for it. It gets linked. It becomes load-bearing.

Naming in public is a commitment, which is why it's worth slowing down. I've shipped features under working names I intended to change and then never did, because the cost of changing them grew faster than my motivation to fix them.

The heuristic I try to use: if I wouldn't be comfortable with this name in a search result in two years, I shouldn't ship with it now. The name is part of the product.
