The audience for most documentation isn't other people. It's you, six months from now, when you've forgotten why you made the decisions you made and need to reconstruct the reasoning without the context that made it obvious at the time.

This reframe changes what documentation is for. It's not a manual. It's a letter to a future collaborator who happens to share your name.

## What future-you needs to know

Future-you already knows how to read code. What future-you doesn't have is the context that was obvious when you wrote it: the constraint you were working around, the alternative you considered and rejected, the reason this approach handles an edge case that isn't immediately visible in the implementation.

Document the context, not the code. If you're writing a comment that says "this function returns a list of users," delete it. The function signature already says that. If you're writing a comment that says "skipping cache here because the auth token refresh race condition from the March incident," keep it.

## The minimum viable document

For this project, the minimum viable documentation ended up being three things: an architecture decision record for every non-obvious choice, inline comments only for surprising behavior, and a single top-level readme that explains the mental model of the system rather than the structure of the files.

The ADR format — context, decision, consequences — forces you to articulate the why before you've forgotten it. Writing it takes ten minutes when the decision is fresh. Reconstructing it takes an hour when it isn't.

## When to write it

The right time to document a decision is immediately after making it, before you've moved on to the next thing. The wrong time is at the end of the project, when the decisions are cold and you're reconstructing rather than recording.

I've started treating documentation as part of the commit, not a separate activity. The commit message is the decision. The code is the implementation. Any necessary context that doesn't fit in the commit message goes in a comment or an ADR. Nothing waits for "later."
